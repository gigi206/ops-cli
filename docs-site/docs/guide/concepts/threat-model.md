# Threat model

For someone deciding whether this tool covers their risk: each row names a threat, the control that answers it and where that control is enforced, and what remains once the control has done its job. The owner page beside each row is authoritative; this page states the shape once, and a remainder that matters to you should be read there end to end. The two pages it compresses are [Security model](security-model) (the guarantee) and [Decisions and limits](decisions) (what is not guaranteed, and what would reopen each choice).

One idea runs under every row: the cage runs as your uid, so **the bind layout is the boundary**. Everything else is depth, and a control below that is not the boundary says so on its own page.

| Threat | Control (where enforced) | What remains | Read more |
|---|---|---|---|
| The agent reads your files and secrets on the host | The host filesystem is absent by default; only a trusted config binds paths in, and an untrusted project gets no binds at all | The project tree itself stays readable, including a `.env` or key beside the code (`[fs] deny` reduces exposure, with stated non-coverage); anything the agent writes that you later run on the host (a `postinstall` script, a `Makefile` recipe, a hook, a CI workflow) crosses the boundary afterwards, by you | [Confidentiality by absence](security-model#same-uid-confidentiality-by-absence), [Where the protection stops](security-model#where-the-protection-stops), [`[fs]`](../configuration/fs) |
| The agent sends data out over the network | The cage lives in an empty network namespace; the only exit is a host-side proxy enforcing a deny-by-default allowlist, with DNS resolved host-side. An untrusted project's `network` is dropped in both directions | An allowed host is allowed: the proxy does not see inside a permitted connection, and a capture has shapes it cannot reassemble. `shared` removes filtering entirely | [Networking](../networking/), [Security-gated](../networking/modes#security-gated), [What a capture does not cover](../networking/observability#what-a-capture-does-not-cover) |
| The agent escapes to the host kernel | bubblewrap (all namespaces, `no_new_privs`, dropped capabilities) with an always-on seccomp denylist; capability-bearing user namespaces are a hard requirement, checked by `sbx doctor` | seccomp is surface reduction, not the boundary, and a trusted config may re-permit a syscall. Exposed device nodes and GPU access widen driver surface the filter does not cover | [Enforcement stack](enforcement), [Why seccomp stays surface reduction](../configuration/seccomp#why-it-stays-surface-reduction-not-a-boundary) |
| The agent exhausts host resources | cgroup v2 ceilings over built-in defaults, applied to every cage a launch stands up | Best-effort, never the boundary: applied where the host supports them, skipped where it does not | [`[limits]`](../configuration/limits), [Best-effort, never the boundary](enforcement#best-effort-never-the-boundary) |
| The agent runs a dangerous program | `[proc]` `enforce` or `ask` decides every `execve` in the whole process tree from a host-side supervisor | Off by default; a denylist, so what is not named runs | [`[proc]`](../configuration/proc) |
| A credential the agent uses leaks to the agent | The never-in-cage invariant: values resolve host-side and are injected into matching outbound requests on the wire, scoped to the declared host. Resolver plugins run in cages of their own; brokers and the ssh-agent fence non-HTTP resources the same way | The outbound and inbound tripwires are backstops with a stated evasion, not the boundary. A credential the cage acquires by itself (an in-cage OAuth sign-in) is contained, not absent | [Secrets](../secrets/), [Honest scope of redaction](../secrets/redaction#honest-scope-these-are-backstops-not-the-boundary), [Broker limits](../configuration/broker#the-honest-limits) |
| The project config itself is the attack | The safety gate refuses a config that is not plain, owner-owned and non-world-writable before parsing it; the trust gate then drops an untrusted project's security fields with a warning, keyed to the file's content hash | The free fields still apply from an untrusted project (`env` minus the reserved keys, `timezone`, and `[fs]` masks, which can only subtract and only union). Trust re-arms on every edit | [The trust gate](trust#the-safety-gate), [Architecture](architecture) |
| The toolchain or userland is tainted or drifts | Versions move only on `sbx upgrade` (seeded, not baked). An image is resolved once to a digest, checked against the bytes served, and mounted read-only. Provisioning runs host-side; the supply-chain fields are trusted-only | Pinning verifies what was fetched, not whether it is trustworthy. In-cage `mise:` tools fetch upstream-direct and ride the allowlist | [Provisioning](provisioning), [`distro`](../configuration/distro), [Upgrading](../housekeeping/upgrade) |
| A privileged operation needs a credential the agent must not hold | A declared `[task]` runs in an ephemeral sibling cage (immutable store, read-only project, fresh home), with caller parameters re-checked against their bounds | Parameter handling and output redaction are accident containment: they catch a credential echoed by mistake, not one a program set out to exfiltrate | [Declared operations](../tasks/), [`[task]`](../configuration/task) |
| The boundary bites and nobody hears it | `[notify]` reports refusals host-side, on the desktop or stderr. The process, filesystem, egress and ssh-agent lenses sit on host-side sockets the cage never sees | A lens is not a fence: only the exec lens enforces, and only egress carries a policy. Records are bounded and live in memory | [`[notify]`](../configuration/notify), [Observability](observability) |
